# NUAAI v1.0.1 Production Dogfood Protocol

## Purpose

Exercise the tagged `v1.0.1` daemon through the authenticated production API with 20 independent real-provider runs. The campaign tests completion truth, canonical tool execution, durable output, and operator-facing recovery behavior. It does not benchmark model prose style.

## Calibration correction

An initial ten-run calibration used arbitrary 40–80 character minimum-output thresholds. Three fully correct concise results demonstrated that answer length was not a valid correctness proxy; for example, an exact working-directory result plus the required case marker needs fewer than 50 characters.

Those calibration runs and the original manifest are preserved in `v1.0.1-calibration-manifest.json`. Calibration runs are excluded from the scored campaign. The scored manifest sets a ten-character non-empty-output floor and relies on stronger behavioral evidence:

- the expected canonical tool completed;
- the required factual terms appear in durable output;
- exactly one terminal event exists and it is `run.completed`;
- no action remains running or failed;
- no false tool-turn-limit output appears.

This correction was frozen before any scored campaign run.

A first scored report then exposed four case-specification issues. The blocked report and JSON are preserved as `v1.0.1-initial-blocked-report.md` and `v1.0.1-initial-blocked-results.json`. The final manifest corrected only those invalid assertions:

- case 02 now asks `AGENTS.md` for the loopback/authentication rule actually present in that file;
- case 08 accepts the measured line count plus case marker without requiring the model to repeat the input path;
- case 16 targets public `example.com`; the prior private Tailscale target was correctly rejected by the SSRF boundary;
- case 18 explicitly requests and accepts the exact numeric repository count without decorative marker text.

The 16 unaffected runs remain evidence. The four corrected cases receive replacement runs, producing 24 total scored attempts with every replacement visible in the preserved blocked report and final report.

## Isolation

- Each case receives a fresh production session and thread.
- Cases execute sequentially to avoid provider or host contention.
- All 20 prompts are read-only.
- No file, memory, schedule, task, provider, GitHub, MCP, or external state mutation is requested.
- The browser submission path records run IDs only; SQLite is the independent evidence source.

## Pass gate

The campaign passes only when:

- exactly 20 scored cases are present;
- at least 18 cases pass;
- no global safety violation occurs;
- durable action and terminal counts reconcile;
- a sampled completed conversation survives reload/reconnect without duplicate assistant output or horizontal overflow.

A percentage cannot override a safety violation.

## Additional controls

Cancellation, retry, and reconnect are reported separately from the 20-case percentage. A control failure blocks the dogfood gate even if the percentage passes.
